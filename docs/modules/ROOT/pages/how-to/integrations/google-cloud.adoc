:page-product: agent-memory

Check Vertex AI embedding output and store a message in Neo4j using that embedder. ADK orchestration, MCP serving and Cloud Run deployment are linked as separate tasks so that this recipe has one observable outcome.

== 1. Prepare the selected environment

Install the Google Cloud CLI (`gcloud`) before configuring Application Default Credentials below.

anchor:_overview[]
anchor:_installation[]

Use Python 3.10+ and the current repository checkout. Start a dedicated Neo4j 5.26+ database; its existing vectors and indexes must match the selected model and dimensions. The program disables entity extraction and does not require a chat model.
[source,bash]
----
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[vertex-ai]"
export GOOGLE_CLOUD_PROJECT='replace-with-your-project-id'
export GOOGLE_CLOUD_LOCATION='us-central1'
export NEO4J_URI='bolt://localhost:7687'
export NEO4J_PASSWORD='replace-with-your-database-password'
gcloud auth application-default login
----

The project needs Vertex AI enabled, billing and a principal authorized to invoke the selected model in that location. This recipe uses Application Default Credentials. The selected `gemini-embedding-001` configuration explicitly requests 768 dimensions; its native dimension count is not the effective value used by this program.

== Troubleshooting and cleanup


Stop when the program raises an exception; a printed model response alone does not verify persistence. Check the configured database, provider access and vector dimensions before retrying. The program prints the session or trace IDs needed for inspection and closes the client. Retained example records remain in the dedicated database; remove that disposable database only when you no longer need them. Reusing a session groups records; it does not authorize a user to read them.

`VertexAIEmbedder` accepts `project_id`, `location`, `task_type` and `output_dimensionality`. Use one consistent model/configuration for both stored document vectors and retrieval. Changing dimensions requires an intentional index/data migration; matching dimension counts alone does not make embeddings from different models compatible. See xref:how-to/configure-embedding-provider.adoc[Configure embeddings] for the canonical model and configuration guidance.

For ADK, use xref:how-to/integrations/google-adk.adoc[the complete Runner recipe]. For memory tools, use xref:how-to/create-context-graph-mcp.adoc[the MCP server guide] and xref:reference/mcp-tools.adoc[the canonical tool reference]. Use xref:reference/deployment.adoc[the deployment reference] and https://github.com/neo4j-labs/agent-memory/tree/main/deploy/cloudrun[the maintained Cloud Run assets] for service deployment, environment configuration and verification; this page does not duplicate a Dockerfile or grant public access.

https://github.com/neo4j-labs/agent-memory/tree/main/examples/google_cloud_integration[The Google Cloud scripts] demonstrate cloud embedding and ADK APIs. https://github.com/neo4j-labs/agent-memory/tree/main/examples/financial-services-advisor/google-cloud-financial-advisor[The financial-advisor application] adds its own specialist agents, domain tools, UI and infrastructure. Those application components are not installed automatically by the memory library, and any real deployment requires the example's own setup and checks.

See xref:reference/backend-capabilities.adoc[Backend capabilities and scoping] before adding hosted or multi-user behavior. Neo4j Agent Memory is a Neo4j Labs project with community support.
