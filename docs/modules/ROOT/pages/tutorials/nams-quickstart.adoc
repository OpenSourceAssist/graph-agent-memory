= Store and read back memory on NAMS
:page-product: agent-memory
:page-pagination:
:toclevels: 2
:sectanchors:

We will create a hosted conversation, read its messages back, wait for its extraction status, and record and retrieve a simulated tool call. We will use the conversation ID returned by NAMS throughout.

This lesson runs the maintained scripts from the current repository checkout in a POSIX shell. Offline checks verify the scripts and selected control flow; successful database, model, or hosted-service execution must still be observed in your environment. It does not claim that an unverified published SDK artifact exposes the same surface.

[[_what_youll_need]]
== Before you begin

* Python 3.10 or newer and Git.
* A dedicated NAMS test workspace and its *workspace key*, using `https://memory.neo4jlabs.com/v1`.
* Permission to create tutorial records in that workspace. Keep the same workspace key throughout the lesson.

See xref:reference/authentication.adoc[Authentication] for obtaining the key before beginning. This path uses a workspace key; admin keys and custom deployments belong in xref:how-to/use-nams.adoc[the NAMS guide].

[[_1_install]]
== 1. Install the current source

[source,bash]
----
git clone https://github.com/neo4j-labs/agent-memory.git
cd agent-memory
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[nams]'
python -c "import neo4j_agent_memory; print('SDK import verified')"
----

Expected: `SDK import verified`. Keep this repository directory as the working directory for every command below.

[[_2_configure]]
== 2. Configure the hosted workspace

[source,bash]
----
export MEMORY_API_KEY="replace-with-your-workspace-key"
export MEMORY_ENDPOINT="https://memory.neo4jlabs.com/v1"
unset MEMORY_WORKSPACE_ID
python -c "from neo4j_agent_memory import NamsSettings; s=NamsSettings(); print(s.backend, s.nams.endpoint)"
----

Expected: `nams https://memory.neo4jlabs.com/v1`. This validates configuration only; it does not authenticate or write data.

[[_4_short_term_memory]]
== 4. Run and verify each stage

anchor:_5_long_term_memory_and_asynchronous_extraction[]anchor:_7_reasoning_memory[]anchor:_10_run_it[]

[source,bash]
----
python docs/modules/ROOT/examples/nams_quickstart.py
----

The program prints these milestones in order:

. `Conversation ID:` followed by the real server ID. Record it for inspection and cleanup.
. `Verified: both messages were read back`. This checks the contents returned by a separate read.
. `Extraction settled; workspace search returned ...`. The wait is finite and a timeout stops the lesson. Candidate count and names depend on the service; workspace search is not proof that every result originated in this conversation.
. `Verified: the simulated tool call was read back`. The tool result is an explicit fixture, not a hardware operation or an inferred internal reasoning trace.

A missing milestone or exception means that stage is not verified. NAMS reassembles reasoning records by conversation, so the script checks actual steps/tool calls rather than a synthetic trace title.

[[_what_just_happened]]
== What we learned

anchor:_which_calls_are_portable[]

The conversation name and its returned ID have different roles. Stored messages can be read back before asynchronous extraction settles. A trace records the actions supplied by an application; in this exercise those actions are simulated.

The Python Bolt and NAMS APIs have different creation and return contracts. Do not switch the settings object and assume this script is portable. See xref:reference/backend-capabilities.adoc[Backend capabilities].

[[_cleanup]]
== Cleanup

The script closes its client and retains the tutorial conversation for inspection. Remove the recorded conversation through the NAMS workspace's supported data-management interface using the printed ID. Extracted entities may be shared with other records and are not claimed to be removed by conversation cleanup. This is why the lesson uses a dedicated test workspace. No write-Cypher cleanup is required.
