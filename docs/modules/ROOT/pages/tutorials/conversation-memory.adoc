= Add persistent conversation context to a chatbot
:page-product: agent-memory
:page-pagination:
:toclevels: 2
:sectanchors:

We will store a shopper's first conversation, stop the process, and answer a new question in a second process using the earlier conversation, an explicit budget preference, and a fictional product. The program passes that retrieved context to a chat model and records the product lookup as a trace.

This lesson uses the Python SDK from the current repository checkout and a dedicated local Bolt database. The complete programs below are maintained as Antora examples. Offline contract tests exercise their assembly and control flow; provider and database success still need to be observed in your environment.

anchor:_prerequisites[]

== Before you begin

* Python 3.10 or newer, Git, and a running Docker engine.
* An OpenAI API key with access to `text-embedding-3-small`.
* Free local ports 7474 and 7687. Stop the database from an earlier lesson before starting this one.

The embedding calls send the supplied text to OpenAI. This exercise uses fictional data. Neo4j Agent Memory is an experimental Neo4j Labs project; see xref:reference/backend-capabilities.adoc[backend capabilities] before adapting the example to NAMS.

You also need an OpenAI chat-model ID available to your account. This lesson sends retrieved conversation text and preferences to that model. The budget is explicitly seeded; automatic preference learning is outside this exercise.

== 1. Install the lesson dependencies

[source,bash]
----
git clone https://github.com/neo4j-labs/agent-memory.git
cd agent-memory
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[openai]'
python -c "import neo4j_agent_memory; print('SDK import verified')"
----

Expected: `SDK import verified`. Keep the repository root as your working directory for every command below.

anchor:_step_2_set_up_neo4j[]

== 2. Start the dedicated database

[source,bash]
----
docker run -d --name neo4j-docs-chat \
  -p 7474:7474 -p 7687:7687 \
  -e NEO4J_AUTH=neo4j/docs-local-password \
  neo4j:5.26-community
python docs/modules/ROOT/examples/wait_for_tutorial_neo4j.py neo4j-docs-chat
----

Expected: `Verified: Neo4j answered the readiness query`. The readiness check stops after three minutes and reports the database error if startup fails.

== 5. Store the first conversation and explicit preference

[source,bash]
----
python docs/modules/ROOT/examples/conversation_memory.py seed
----

Expected: `Stored: first conversation, explicit shopper preference, fictional product`. The process exits and closes its database connection.

anchor:_step_4_test_persistence_across_sessions[]

== 6. Answer a new question after restart

[source,bash]
----
python docs/modules/ROOT/examples/conversation_memory.py resume
----

Expected milestones:

. `Retrieved: 2 prior messages and 1 preferences`.
. `Verified: new response and product-lookup trace read back`.
. A model answer to “What would you recommend for the trip I mentioned?”

Inspect the answer for the seeded wide-fit city-walking requirement, the USD 60 budget, and the fictional Trail Starter product priced at USD 45. Wording and model adherence can vary. The checks prove that the request contained retrieved context and that the resulting answer and tool record were stored; they do not grade recommendation quality.

A model failure completes the trace with `success=False` and raises the error. Fix provider access before retrying. The program does not label a failed request as a successful answer.

anchor:_step_6_add_reasoning_traces[]

== 7. Verify the linked tool record

In Neo4j Browser at `http://localhost:7474`, sign in with the tutorial credentials and run:

[source,cypher]
----
MATCH (trace:ReasoningTrace {session_id: 'docs-shopping-return'})-[:HAS_STEP]->(step:ReasoningStep)-[:USES_TOOL]->(call:ToolCall)
RETURN trace.success, step.action, call.tool_name
----

Expected: a successful trace, the action to read the tutorial product, and the `lookup_product` tool call. If you ran a failed attempt too, inspect each trace separately.

anchor:_what_youve_built[]

== What we built

The second process read persisted context, included it in a real model request, and stored its response with a trace of the product lookup. Retrieval and authorization remain separate responsibilities: an application must authorize the session IDs and user identifier it passes to these APIs. See xref:how-to/multi-tenancy.adoc[multi-tenancy] before extending this single-user exercise.

anchor:_clean_up[]

== Clean up

Remove only the database created for this lesson:

[source,bash]
----
docker rm -f neo4j-docs-chat
----

Expected: Docker prints `neo4j-docs-chat`. This container has no mounted persistent volume, so removing it deletes this lesson's database. Keep the checkout and virtual environment for the next lesson.

anchor:_troubleshooting[]

== If a check fails

* A connection or authentication failure: inspect `docker logs neo4j-docs-chat` and confirm the tutorial password and ports match the helper.
* An OpenAI access or quota error: correct the account/model configuration and rerun on a fresh tutorial database if the prior write stopped midway.
* Missing readback data: verify that the write command completed against this container. The program stops on missing data rather than treating an empty result as success.
