= Hosted TypeScript Quickstart
:description: Store and read back a conversation using the hosted REST service and TypeScript SDK.
:toc:
:source-highlighter: rouge

Create a conversation, store a message, retrieve its context, and record an
application-authored activity step. This path needs a NAMS key and no model API
key. Allow about ten minutes after installing Node.js.

anchor:_prerequisites[]
anchor:_step_2_install_a_client[]

== Step 1: Build the SDK and install the lesson project

This lesson uses the current source checkout. It does not establish which npm
release contains these APIs. Use Node.js 22 or later; the lesson project declares
AI SDK 7 and `@ai-sdk/openai` 4. You need a `MEMORY_API_KEY` for a test workspace
on link:https://memory.neo4jlabs.com/[NAMS]. This quickstart does not call a model, so `OPENAI_API_KEY` is not required.

From the repository root, run:

[source,bash]
----
cd typescript
npm ci
npm run build
cd examples/vercel-ai
npm ci
cp .env.example .env
----

Edit `.env` with your keys. Keep it out of version control. All remaining commands
run in `typescript/examples/vercel-ai/`. Its `package.json` sets ESM and its
`tsconfig.json` supplies the compiler settings; no global TypeScript install is needed.
Run `npm run lint` to verify the complete programs against your checkout.

== Step 2: Inspect the complete program

Open `src/tutorials/hosted-quickstart.ts`:

[source,typescript]
----
import { MemoryClient } from "@neo4j-labs/agent-memory";
import { pathToFileURL } from "node:url";

export async function hostedQuickstart(client: MemoryClient) {
  const conversation = await client.shortTerm.createConversation({ userId: "tutorial-reader" });
  console.log(`CONVERSATION_ID=${conversation.id}`);
  await client.shortTerm.addMessage(conversation.id, "user", "I am planning the fictional Lantern Orchard project.");
  const stored = await client.shortTerm.getConversation(conversation.id);
  const context = await client.shortTerm.getContext(conversation.id);
  console.log(`Stored messages: ${stored.messages.length}`);
  console.log(`Recent context messages: ${context.recentMessages.length}`);
  await client.reasoning.recordStep({
    conversationId: conversation.id,
    reasoning: "Verified that the submitted message can be read back.",
    actionTaken: "verify_storage",
    result: `Read ${stored.messages.length} message(s)`,
  });
  const trace = await client.reasoning.getTraceByConversation(conversation.id);
  console.log(`Recorded steps: ${trace.steps.length}`);
  return conversation.id;
}

if (process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href) {
  const client = new MemoryClient({ endpoint: process.env.MEMORY_ENDPOINT });
  try {
    if (!process.env.MEMORY_API_KEY) throw new Error("Set MEMORY_API_KEY.");
    await hostedQuickstart(client);
  } finally { await client.close(); }
}
----

anchor:_step_1_sanity_check_the_service[]
The first request validates authentication. `createConversation` supplies the id
used by every later operation. The activity record describes this program's
storage check; it does not claim an extraction or entity-provenance link.

== Step 3: Run the storage check

[source,bash]
----
npx tsx --env-file-if-exists=.env src/tutorials/hosted-quickstart.ts
----

Expect a new conversation id, `Stored messages: 1`, one recent context message
and `Recorded steps: 1`. A successful message write does not mean asynchronous
entity extraction has finished. The next tutorial handles that distinction.

== Clean up the conversation

Keep the printed conversation id. From the same lesson directory, delete that
specific conversation when you have finished inspecting it:

[source,bash]
----
CONVERSATION_ID='<the printed id>' npx tsx --env-file-if-exists=.env src/tutorials/conversation.ts cleanup
----

Closing the client only releases client resources. It does not delete stored
messages. Deleting a conversation does not promise removal of extracted,
workspace-wide entities; inspect those separately in a disposable test workspace.
