= Store and recall a message from Claude Desktop
:page-product: agent-memory
:page-pagination:
:toclevels: 2
:sectanchors:

We will connect Claude Desktop on macOS to a local stdio MCP server, explicitly request a message-storage tool call, and verify that record in Neo4j before retrieving it. The server does not automatically capture all chat turns merely because it is connected.

This lesson selects the core tool profile, a local embedding model, and disabled entity/preference extraction. Remote hosting and other profiles are separate how-to tasks.

This lesson runs the maintained scripts from the current repository checkout in a POSIX shell. Offline checks verify the scripts and selected control flow; successful database, model, or hosted-service execution must still be observed in your environment. It does not claim that an unverified published SDK artifact exposes the same surface.

[[_what_youll_learn]]
== Before you begin

anchor:_prerequisites[]anchor:_time_required[]

* macOS with Claude Desktop installed and support for local MCP servers enabled.
* Python 3.10 or newer, Git, Docker, and free local ports 7474/7687.
* Space and network access for the initial sentence-transformer model download.

Claude Desktop's interface can vary by release. The verification target is the visible tool invocation and stored database record, not a particular icon or generated sentence.

[[_step_1_start_neo4j]]
== 1. Install and start Neo4j

anchor:_step_2_install_neo4j_agent_memory[]

[source,bash]
----
git clone https://github.com/neo4j-labs/agent-memory.git
cd agent-memory
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[mcp,sentence-transformers]'
python -c "import neo4j_agent_memory; print('SDK import verified')"
----

Expected: `SDK import verified`. Keep this repository directory as the working directory for every command below.

[source,bash]
----
docker run -d --name neo4j-docs-mcp \
  -p 7474:7474 -p 7687:7687 \
  -e NEO4J_AUTH=neo4j/docs-local-password \
  neo4j:5.26-community
python docs/modules/ROOT/examples/wait_for_tutorial_neo4j.py neo4j-docs-mcp
----

Expected: `Verified: Neo4j answered the readiness query`. The check stops after three minutes; resolve a startup failure before continuing.

[source,bash]
----
python docs/modules/ROOT/examples/mcp_local_tutorial.py --prepare
----

Expected: `Verified: local embedding model returned 384 dimensions`. This prepares the model before Claude Desktop starts the server, avoiding an unobserved first-start download.

[[_step_3_configure_claude_desktop]]
== 2. Configure the local stdio process

anchor:_programmatic_server_usage[]

The maintained server program uses the current virtual environment and explicit Bolt settings:

[source,python]
----
include::example$mcp_local_tutorial.py[]
----

Generate the configuration with absolute interpreter and script paths:

[source,bash]
----
python docs/modules/ROOT/examples/mcp_local_tutorial.py --config > mcp-tutorial-config.json
python -m json.tool mcp-tutorial-config.json
----

Expected: a `mcpServers` entry named `neo4j-docs` whose `command` and script argument are absolute paths. Merge that one entry into `~/Library/Application Support/Claude/claude_desktop_config.json`, preserving any existing servers. Restart Claude Desktop to load it. Do not run a second copy of the server manually: Claude Desktop launches the stdio process.

[[_step_4_verify_the_connection]]
== 3. Verify the tool connection

In a new Claude Desktop conversation, inspect the tools provided by `neo4j-docs`. Confirm that `memory_store_message` and `memory_search` are available.

Ask Claude: "Use the neo4j-docs memory_search tool to search for cedar-lantern-47. Show whether the tool found a stored result."

Expected: a visible tool invocation and a result or an empty result. A chat response without a tool call does not verify the connection.

[[_step_5_have_a_memory_aware_conversation]]
== 4. Store one exact message

Ask Claude:

[quote]
Use neo4j-docs memory_store_message with session_id "claude-docs-tutorial", role "user", and content "The workshop passphrase is cedar-lantern-47." Report the returned storage result.

Expected: a visible `memory_store_message` invocation with those arguments and a successful tool result. The supplied Bolt session ID organizes this exercise; it is not an authorization boundary. No extracted entity or preference is required for this lesson.

[[_step_6_verify_in_neo4j_browser]]
== 5. Verify the stored record

Open `http://localhost:7474`, log in as `neo4j` with `docs-local-password`, and run:

[source,cypher]
----
MATCH (conversation:Conversation {session_id: 'claude-docs-tutorial'})-[:HAS_MESSAGE]->(message:Message)
WHERE message.content = 'The workshop passphrase is cedar-lantern-47.'
RETURN message.id, message.content
----

Expected: at least one row with the exact passphrase message and its stored ID. Repeating the storage request may create another message, so inspect the result before retrying.

[[_step_7_test_memory_recall]]
== 6. Retrieve through the tool

Start a fresh Claude Desktop conversation and ask:

[quote]
Use neo4j-docs memory_search for "workshop passphrase" with session_id "claude-docs-tutorial". Quote the stored passphrase only if the tool returns it.

Expected: a visible search invocation whose result contains `cedar-lantern-47`. An answer inferred from earlier chat text is not proof of retrieval; compare the tool result with the database row from the preceding step.
