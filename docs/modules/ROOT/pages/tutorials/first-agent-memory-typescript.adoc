= Build Your First TypeScript Agent with Memory
:toc:
:source-highlighter: rouge

anchor:_what_youll_build[]
Build an agent that stores a fictional project name and entity, retrieves context from the same
conversation during a model call, and records an application-authored activity step.
Allow about 15 minutes. The hosted REST service stores the data; no Neo4j server
is needed on your machine.

== Step 1: Build the SDK and install the lesson project

This lesson uses the current source checkout. It does not establish which npm
release contains these APIs. Use Node.js 22 or later; the lesson project declares
AI SDK 7 and `@ai-sdk/openai` 4. You need a `MEMORY_API_KEY` for a test workspace
on link:https://memory.neo4jlabs.com/[NAMS]. Model calls also need `OPENAI_API_KEY`.

From the repository root, run:

[source,bash]
----
cd typescript
npm ci
npm run build
cd examples/vercel-ai
npm ci
cp .env.example .env
----

Edit `.env` with your keys. Keep it out of version control. All remaining commands
run in `typescript/examples/vercel-ai/`. Its `package.json` sets ESM and its
`tsconfig.json` supplies the compiler settings; no global TypeScript install is needed.
Run `npm run lint` to verify the complete programs against your checkout.

== Step 2: Read the complete agent

Open `src/tutorials/first-agent.ts`. The file below is the complete program; keep
its imports at module scope. It first prints a real conversation id, then stores
a message under that id. The search explicitly scopes itself to that conversation.

[source,typescript]
----
import type { LanguageModelV4 } from "@ai-sdk/provider";
import { openai } from "@ai-sdk/openai";
import { generateText, wrapLanguageModel } from "ai";
import { agentMemoryMiddleware } from "@neo4j-labs/agent-memory/middleware/vercel-ai";
import { MemoryClient } from "@neo4j-labs/agent-memory";
import { pathToFileURL } from "node:url";

export async function firstAgent(client: MemoryClient, baseModel: LanguageModelV4) {
  const conversation = await client.shortTerm.createConversation({ userId: "tutorial-alice" });
  console.log(`CONVERSATION_ID=${conversation.id}`);
  const message = await client.shortTerm.addMessage(
    conversation.id, "user", "My fictional project is called Lantern Orchard.",
  );
  console.log(`Stored message: ${message.id}`);
  const matches = await client.shortTerm.searchMessages("Lantern Orchard", {
    conversationId: conversation.id, limit: 5,
  });
  console.log(`Conversation search matches: ${matches.length}`);

  const entity = await client.longTerm.addEntity(`Lantern Orchard ${conversation.id}`, "organization", {
    description: "Fictional organization used by this tutorial run.",
  });
  const storedEntity = await client.longTerm.getEntity(entity.id);
  console.log(`ENTITY_ID=${storedEntity.id} name=${storedEntity.name}`);

  const model = wrapLanguageModel({
    model: baseModel,
    middleware: agentMemoryMiddleware(client, { conversationId: conversation.id }),
  });
  const answer = await generateText({
    model,
    system: "Use the supplied conversation history. If a fact is missing, say so.",
    prompt: "What is my project called?",
  });
  console.log(answer.text);
  // This is an application-authored activity record, not hidden model reasoning.
  await client.reasoning.recordStep({
    conversationId: conversation.id,
    reasoning: "Loaded the same conversation before answering the recall question.",
    actionTaken: "answer_with_memory",
    result: answer.text,
  });
  const trace = await client.reasoning.getTraceByConversation(conversation.id);
  console.log(`Recorded steps: ${trace.steps.length}`);
  return { conversationId: conversation.id, entityId: entity.id, answer: answer.text };
}

if (process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href) {
  const client = new MemoryClient({ endpoint: process.env.MEMORY_ENDPOINT });
  try {
    if (!process.env.MEMORY_API_KEY || !process.env.OPENAI_API_KEY) {
      throw new Error("Set MEMORY_API_KEY and OPENAI_API_KEY.");
    }
    await firstAgent(client, openai(process.env.OPENAI_MODEL ?? "gpt-4o-mini"));
  } finally { await client.close(); }
}
----

anchor:_step_6_add_vercel_ai_sdk_middleware[]
`wrapLanguageModel` accepts the SDK's V4 middleware. Before generation, the
middleware reads this conversation's reflections, observations and recent
messages; after a non-streaming generation it awaits the assistant-message write.
The model receives the previously stored project name even though the new question
contains neither the name nor the original message.

== Step 3: Run and inspect the result

[source,bash]
----
npx tsx --env-file-if-exists=.env src/tutorials/first-agent.ts
----

Expect a `CONVERSATION_ID`, a stored message id, a search-result count, an `ENTITY_ID` read back by id, a model
answer mentioning Lantern Orchard, and `Recorded steps: 1`. IDs, search counts
and model wording vary. A fresh conversation may have no observations or reflections;
recent messages are sufficient for this example. Readback proves storage;
an entity search or an LLM answer alone does not prove storage.

The activity step is text supplied by this program. It does not expose the
model's hidden reasoning. Hosted reasoning uses `recordStep` and
`getTraceByConversation`; legacy trace lifecycle methods require the conformance bridge.

== Clean up the conversation

Keep the printed conversation id. From the same lesson directory, delete that
specific conversation when you have finished inspecting it:

[source,bash]
----
CONVERSATION_ID='<the printed id>' npx tsx --env-file-if-exists=.env src/tutorials/conversation.ts cleanup
----

Closing the client only releases client resources. It does not delete stored
messages. Deleting a conversation does not promise removal of extracted,
workspace-wide entities; inspect those separately in a disposable test workspace.

The explicitly added entity id is printed separately. After inspecting it,
delete it with `client.longTerm.deleteEntity(entityId)` only if it belongs to
this test and was not merged with shared data. Entity storage is workspace-wide.
