= Build your first memory context
:page-product: agent-memory
:page-pagination:
:toclevels: 2
:sectanchors:

We will store a short conversation, a relationship between two entities, and an explicit preference. We will close the process, retrieve those records in a second process, and assemble context that an application can pass to a model. This lesson builds the memory input; the xref:tutorials/conversation-memory.adoc[next lesson] uses that input in a chatbot.

image::diagrams/message-chain.svg["A conversation linked to an ordered chain of messages",width=100%,link=self]

This lesson uses the Python SDK from the current repository checkout and a dedicated local Bolt database. The complete programs below are maintained as Antora examples. Offline contract tests exercise their assembly and control flow; provider and database success still need to be observed in your environment.

anchor:_prerequisites[]

== Before you begin

* Python 3.10 or newer, Git, and a running Docker engine.
* An OpenAI API key with access to `text-embedding-3-small`.
* Free local ports 7474 and 7687. Stop the database from an earlier lesson before starting this one.

The embedding calls send the supplied text to OpenAI. This exercise uses fictional data. Neo4j Agent Memory is an experimental Neo4j Labs project; see xref:reference/backend-capabilities.adoc[backend capabilities] before adapting the example to NAMS.

== 1. Install the lesson dependencies

[source,bash]
----
git clone https://github.com/neo4j-labs/agent-memory.git
cd agent-memory
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[openai]'
python -c "import neo4j_agent_memory; print('SDK import verified')"
----

Expected: `SDK import verified`. Keep the repository root as your working directory for every command below.

anchor:_step_2_set_up_neo4j[]

== 2. Start the dedicated database

[source,bash]
----
docker run -d --name neo4j-docs-first \
  -p 7474:7474 -p 7687:7687 \
  -e NEO4J_AUTH=neo4j/docs-local-password \
  neo4j:5.26-community
python docs/modules/ROOT/examples/wait_for_tutorial_neo4j.py neo4j-docs-first
----

Expected: `Verified: Neo4j answered the readiness query`. The readiness check stops after three minutes and reports the database error if startup fails.

anchor:_step_6_add_user_preferences[]

== 5. Read the persisted records in a second process

[source,bash]
----
python docs/modules/ROOT/examples/first_agent_memory.py verify
----

Expected: `Verified: stored history, preference, and relationship survived restart`, followed by the two stored messages, `Preference: Use concise answers`, and `Maya Chen works at Northstar Robotics`.

The history lookup uses the known session ID, and preference retrieval uses the known user identifier. These identifiers organize data; your application must authorize the caller before choosing them. The small demonstration database has a single application user.

anchor:_step_8_search_your_context_graph[]

== 6. Compare semantic retrieval with exact readback

[source,bash]
----
python docs/modules/ROOT/examples/first_agent_memory.py search
----

Expected: up to five entity names and their `metadata["similarity"]` values, followed by the candidate count. Scores and order vary. Semantic retrieval is a ranked candidate search; the exact relationship query in step 5 is the persistence check. An empty search string is not an API for listing all entities.

anchor:_step_7_view_your_context_graph_in_neo4j_browser[]

== 7. Inspect the stored relationship

Open `http://localhost:7474` and sign in as `neo4j` with `docs-local-password`. Run:

[source,cypher]
----
MATCH (person:Entity {name: 'Maya Chen'})-[r:RELATED_TO]->(company:Entity)
RETURN person.name, r.relation_type, company.name
----

Expected: Maya Chen, WORKS_AT, and Northstar Robotics. The SDK stores the logical relationship name as `relation_type` on a `RELATED_TO` relationship.

anchor:_what_youve_built[]

== What we built

A program now reconstructs memory context from persistent records. We verified storage independently of semantic ranking. Continue with xref:tutorials/conversation-memory.adoc[conversation memory] to consume retrieved context in an actual model call, or xref:tutorials/knowledge-graph.adoc[document extraction] to generate candidate entities from text.

anchor:_clean_up[]

== Clean up

Remove only the database created for this lesson:

[source,bash]
----
docker rm -f neo4j-docs-first
----

Expected: Docker prints `neo4j-docs-first`. This container has no mounted persistent volume, so removing it deletes this lesson's database. Keep the checkout and virtual environment for the next lesson.

anchor:_troubleshooting[]

== If a check fails

* A connection or authentication failure: inspect `docker logs neo4j-docs-first` and confirm the tutorial password and ports match the helper.
* An OpenAI access or quota error: correct the account/model configuration and rerun on a fresh tutorial database if the prior write stopped midway.
* Missing readback data: verify that the write command completed against this container. The program stops on missing data rather than treating an empty result as success.
