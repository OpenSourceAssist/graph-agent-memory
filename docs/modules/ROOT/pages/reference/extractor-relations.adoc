== GLiRELExtractor

Relation extraction consumes previously extracted entities with span positions. Import from `neo4j_agent_memory.extraction`.

The SDK does not define a `glirel` extra, so install the `glirel` package separately alongside `neo4j-agent-memory`. Its current release also requires `loguru` at import time without declaring that dependency, so install `loguru` explicitly too. GLiREL 1.2.1 also needs `protobuf` and `huggingface-hub` below 1.0 to load its model. `GLiRELExtractor` tokenizes text with spaCy, so it also needs the `spacy` extra and the `en_core_web_sm` model (`python -m spacy download en_core_web_sm`); without them `extract_relations` raises `ImportError` or `RuntimeError`. In `neo4j-agent-memory` 0.6.0, `extract_relations` passes character offsets where GLiREL expects token positions, so it returns no relations; use the LLM extractor for relations on that release. xref:how-to/entity-extraction-schemas.adoc#_relationship_extraction[Extract relationships] shows the install command for the SDK, `glirel`, `loguru`, and spaCy.

// contract: extraction/gliner_extractor.py:GLiRELExtractor.__init__
[source,python]
----
def GLiRELExtractor(
    model: str=DEFAULT_GLIREL_MODEL,
    relation_types: dict[str, str] | list[str] | None=None,
    threshold: float=0.5,
    device: str='cpu',
): ...
----

[cols="1,4",options="header"]
|===
| Parameter | Description
| `model` | GLiREL model name from HuggingFace
| `relation_types` | Relation types to extract: a `dict[str, str]` of names to descriptions (recommended), a `list[str]` of names, or `None` for the default POLE+O relation types.
| `threshold` | Confidence threshold for including relations
| `device` | Device to run on (cpu, cuda, mps)
|===

=== extract_relations

Extract relations between entities using GLiREL.

// contract: extraction/gliner_extractor.py:GLiRELExtractor.extract_relations
[source,python]
----
async def extract_relations(
    text: str,
    entities: list[ExtractedEntity],
    *,
    relation_types: list[str] | None=None,
) -> list[ExtractedRelation]: ...
----

[cols="1,4",options="header"]
|===
| Parameter | Description
| `text` | The source text
| `entities` | Pre-extracted entities (from GLiNER or other extractor)
| `relation_types` | Optional list of relation types to extract. Defaults to all configured relation types.
|===

[source,python]
----
from neo4j_agent_memory.extraction import GLiNEREntityExtractor, GLiRELExtractor

entity_result = await GLiNEREntityExtractor.for_poleo().extract(text)
relations = await GLiRELExtractor().extract_relations(text, entities=entity_result.entities)
for relation in relations:
    print(relation.source, relation.relation_type, relation.target)
----


== GLiNERWithRelationsExtractor

Combine entity and relation extractors. `for_schema` takes a built-in schema *name*, not an EntitySchemaConfig. For custom descriptions, construct a GLiNEREntityExtractor with DomainSchema and a GLiRELExtractor with relation types, then compose them.

// contract: extraction/gliner_extractor.py:GLiNERWithRelationsExtractor.__init__
[source,python]
----
def GLiNERWithRelationsExtractor(
    entity_extractor: GLiNEREntityExtractor,
    relation_extractor: GLiRELExtractor,
): ...
----

=== extract

Extract entities and relations from text.

async def extract(
    text: str,
    *,
    entity_types: list[str] | None=None,
    relation_types: list[str] | None=None,
    extract_relations: bool=True,
    extract_preferences: bool=False,
) -> ExtractionResult: ...
----

[cols="1,4",options="header"]
|===
| Parameter | Description
| `text` | The text to extract from
| `entity_types` | Optional list of entity types to extract
| `relation_types` | Optional list of relation types to extract
| `extract_relations` | Whether to extract relations (default True)
| `extract_preferences` | Ignored (GLiNER/GLiREL don't extract preferences)
|===

=== for_schema

Create combined extractor for a domain schema.

// contract: extraction/gliner_extractor.py:GLiNERWithRelationsExtractor.for_schema
[source,python]
----
def for_schema(
    schema_name: str,
    *,
    gliner_model: str=DEFAULT_GLINER2_MODEL,
    glirel_model: str=DEFAULT_GLIREL_MODEL,
    entity_threshold: float=0.5,
    relation_threshold: float=0.5,
    device: str='cpu',
    relation_types: dict[str, str] | None=None,
) -> GLiNERWithRelationsExtractor: ...
----

[cols="1,4",options="header"]
|===
| Parameter | Description
| `schema_name` | Domain schema name (poleo, podcast, news, etc.)
| `gliner_model` | GLiNER model for entity extraction
| `glirel_model` | GLiREL model for relation extraction
| `entity_threshold` | Confidence threshold for entities
| `relation_threshold` | Confidence threshold for relations
| `device` | Device to run models on
| `relation_types` | Custom relation types (defaults to POLE+O relations)
|===

=== for_poleo

Create combined extractor optimized for POLE+O extraction.

// contract: extraction/gliner_extractor.py:GLiNERWithRelationsExtractor.for_poleo
[source,python]
----
def for_poleo(
    *,
    gliner_model: str=DEFAULT_GLINER2_MODEL,
    glirel_model: str=DEFAULT_GLIREL_MODEL,
    entity_threshold: float=0.5,
    relation_threshold: float=0.5,
    device: str='cpu',
) -> GLiNERWithRelationsExtractor: ...
----

[cols="1,4",options="header"]
|===
| Parameter | Description
| `gliner_model` | GLiNER model for entity extraction
| `glirel_model` | GLiREL model for relation extraction
| `entity_threshold` | Confidence threshold for entities
| `relation_threshold` | Confidence threshold for relations
| `device` | Device to run models on
|===

[source,python]
----
from neo4j_agent_memory.extraction import GLiNERWithRelationsExtractor

extractor = GLiNERWithRelationsExtractor.for_poleo()
result = await extractor.extract("John works at Acme Corp")
print(result.entities, result.relations)
----

`DEFAULT_GLIREL_MODEL` is `jackboyla/glirel-large-v0`. The combined extractor calls `GLiRELExtractor.extract_relations`, so on 0.6.0 `result.relations` is empty for the reason given under <<_glirelextractor,GLiRELExtractor>>. Model output varies; validate entity names, types, and relation endpoints on representative data.
